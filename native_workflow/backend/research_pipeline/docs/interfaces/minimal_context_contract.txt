Minimum sufficient ContextBuilder input contract — 2026-10-14

Normative source: canonical workflow_governance.json, version 1.6.1, G005.
Scope: every workflow step; every ContextBuilder route must declare a task profile.
Host profile registry: resources/context_builder/minimal_context.v1.json.

The model receives only the semantic material it needs to complete the assigned
task under its response contract. Full input retention on the host is a separate
responsibility and is not a reason to repeat full upstream objects in the prompt.

Keep inline: task objective and stage boundary; applicable operative Rules with
conditions/exceptions; necessary evidence and uncertainty; method inputs needed by
the task; identifiers with definitions when output attribution or scientific
relationships require them. Keep hashes, archive/database/chunk bookkeeping,
unneeded local audit paths and complete provenance ledgers on the host.
Do not recursively strip every ID or path: scientific identity, source location,
experimental-unit links and task-required tool paths can be semantically necessary.

Planning reads task-relevant design distinctions, without the full per-table inventory or source-note history. Coverage and independent source
review retain the complete permitted basis required by their task. Preparation
keeps exact assigned source values and experimental-unit identities. Necessity
reads accepted coverage and recorded gaps. Human summary reads accepted decisions.
Unknown routes require an explicit profile; do not default to an entire payload.

Neither hard truncation nor dropping rules is a valid optimization. Exact repeated
text can be stored once with clear occurrence/scope links; this cannot turn separate
experimental units into one entity. Avoid opaque compression and reference mazes.
Optional retrieval requires a concrete unanswered question; supplied definitions do not trigger duplicate background. Zero external background is valid. Retrieval respects permitted source/method scope;
it never replaces mandatory evidence or promotes external text to project authority.

The host records why each section is visible or host-only, binds exact versions,
checks operative rules and evidence restrictions, and verifies valid output
references. Report actual model-visible length and token-count status separately.
Small inputs and passing schema/tests do not establish scientific or model quality.

Historical requests and approvals keep their recorded governance and code versions.
New rules do not reauthorize old outputs. No model run, fitting or release is
authorized by updating this specification.

Upstream semantic handoff (projection 1.4)
Necessity keeps accepted coverage, each shortage, scope and counterevidence, plus
complete candidate profile conditions and limits. Method bibliography and library
integrity lineage stay host-side; supplied definition or citation selectors do not
become scientific approval. Human summaries preserve accepted decisions, affected
scope, holds, uncertainty, conditions and material numbers without a fresh audit.

Downstream preparation, handoff, impact and source-assessment calls inherit already
published Rules. A per-rule publication reference and projection version identify
that handoff. Derivation/routing audit may stay host-side; operative text, conditions,
exceptions, scope, requirement, usage, stages and context_path stay visible. This
does not remove source or candidate evidence from independent review assignments.
Coverage, DP/DH supplied record scope and EDA plan/result/figure/counterevidence
remain complete. Exact repeated prose can share descriptive local text references;
every original identity, occurrence and scope association remains reconstructible.

Common task orchestration (projection 1.5)
context_task.assemble is shared by registered workflow steps. Each route declares
rule collection paths, permitted method-reference fields and a retrieval boundary.
No new retrieval is the default; supplied upstream artifacts pass directly to the
next stage. DR, Necessity and EP may declare independent unanswered method questions;
Coverage, summaries, extraction and independent review use their assigned basis.
The RAG plugin freezes its packet before final request hashing. Host task bindings
travel inside the request and are removed from the model view, so reconstruction
at a provider gateway cannot lose library/source version checks.
Optional method-reference scope uses a complete hash-bound section catalogue,
retaining exact selected text, global constraints and transitive dependencies.
It cannot select or prune Rules, assigned evidence, handoff results or counterevidence.
Unknown steps need explicit route/profile and scientific stage-adapter registration;
generic orchestration does not implement or enable an unfinished scientific stage.

Decision-oriented task sufficiency
Minimum context means sufficient information to complete the current task. Stage
adapters supply the downstream uses that change its questions or outputs, with
their conditions and limitations; they do not supply an unrelated workflow graph.
The shared builder preserves these declared needs through projection and request
binding. Available software handlers limit execution, not the scientific scope
of planning. A relevant output with absent inputs, an unimplemented operation or
a downstream responsibility keeps an explicit local disposition and reason.

For EDA, EP considers the conditional display and descriptive-calculation
catalogue against those needs. A figure, shared panel or table may answer several
questions; exhaustive consideration does not mandate every catalogue image.
EC executes established, supported descriptive formulas, and EV uses those exact
results. Parameter estimation, PD-target fitting and other deferred responsibilities
remain downstream. Planning completeness does not redo Data Coverage or Necessity,
invent missing evidence, qualify a model or approve scientific release.
