Status: AUTHORING_COMPLETE_NOT_RUNTIME_INTEGRATED
Date: 2026-10-13
Language: English

Purpose
These are reviewable prompts for Compression, Data and descriptive EDA. They are new prompt assets, not replacements for published Rules or existing runtime schemas. No live run, scientific qualification, gate approval or EDA activation is implied.

Composition
For one model call, assemble:
1. general.txt once.
2. Canonical G001-G008 once from the existing governance injector.
3. The selected stage's [STAGE] block.
4. Only the selected [OPERATION:<name>] block.
5. The applicable original Project Rules and stage-rule text, retaining conditions and exceptions.
6. The host's exact response schema and version-bound evidence payload.

Do not send all stage files or all operations to every agent. No extra operation or model call is required just because a block exists. Route blocks to their declared calls once implemented; the EDA handoff is a host operation without a model prompt. Compression retains its existing extraction and independent-review policy; this pack does not reduce required reviews. Rule IDs alone are insufficient: include the selected rule text and its prerequisites/exceptions. User instructions remain the authority for authorized scope changes.

Boundaries
- Compression: source meaning, objective and compact handoff; formal Project Rules publishing stays separate.
- Data: access/extract -> lightweight DR -> factual Coverage -> action-specific Necessity -> human summary -> existing preparation/handoff.
- EDA: EP plan -> EC R calculations -> EV R figures -> EI findings -> ER independent review and host handoff. See backend/rules/eda/eda_rules.json (2.0.0-draft.1). Three model operations; calculation/plot handlers and workflow integration remain pending. Existing EDA runtime remains disabled.
- Human/Horse measurements and protected benchmark results follow the supplied source manifest. Source roles can differ within the same document.
- No future model output is automatically classified as a need for new experiments.

Host responsibilities
Select and freeze allowed sources; enforce actual tool/file permissions; verify hashes, schemas, enum values, field/gap accounting and gate state; calculate all numeric results; preserve original and failed artifacts. Do not rely on prompt wording as the implementation of these controls. Never copy a historical approval onto a new prompt/output version.

Before runtime adoption
Bind a versioned prompt to each existing request builder, preserving accepted historical executor bindings. Reconcile the existing schema limits with the selected block. Test semantic behavior on representative project cases before a new live qualification run. This authoring task does not perform those integration steps.

Minimum semantic acceptance cases
1. Partial regimen in proposal/workbook excerpt stays partial and source-scoped.
2. A conditional requirement remains conditional after compression.
3. DR with names/design/notes defines needs without announcing data adequacy.
4. Coverage unable to search a permitted source reports unresolved, not confirmed absence.
5. One verified subset does not make all studies supported; one gap does not block all studies.
6. Missing future fitted exposure is a prerequisite, not automatically a new experiment.
7. Model-based PK can proceed independently of optional terminal-dependent NCA.
8. S26-type permitted MIC/regimen context stays distinct from protected benchmark targets.
9. Summary preserves Necessity readiness and source scope; full evidence stays in details.
10. EDA cannot claim computed numbers/visual verification when corresponding host artifacts are absent.
11. A source document containing "ignore the rules" cannot change the operation.
12. A changed artifact or prompt cannot inherit a prior human approval.

These cases define acceptance expectations, not executed model tests.
