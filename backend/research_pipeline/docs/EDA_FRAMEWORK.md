# EDA framework

Version: 2.0.0-draft.1 | Status: framework built; scientific executors and runtime integration pending.

EDA describes animal PK and preclinical PD evidence and its limitations in support of later prospective human exposure prediction and assessment of potentially efficacious doses/regimens, feasibility and uncertainty. The current target-drug setting has no human PK/PD, efficacy or safety observations. Human predictions and protected known-drug benchmarks remain separate.

## Five components

| ID | Name | Execution | Responsibility | Output contract |
|---|---|---|---|---|
| EP | EDA Planner | Model | Accept verified Data scope; choose calculations and displays with explicit axes, groups and purpose | `eda_plan` |
| EC | EDA Calculator | R | Execute established descriptive formulas; retain input relationships, experimental units and provenance | `calculation_bundle` |
| EV | EDA Visualizer | R / ggplot2 | Draw from EC results and permitted observations; check figure/data correspondence | `figure_bundle` |
| EI | EDA Interpreter | Model | Describe observations, limits and implications for later analysis | `eda_findings` |
| ER | EDA Reviewer & Handoff | Independent model review; Python host assembly | Review evidence and outputs, route corrections, then assemble the reviewed and human-confirmed version | `eda_review`, `eda_handoff` |

```text
Verified Data handoff + task context + shared scientific reference
  -> EP: plan
  -> EC: descriptive calculations in R
  -> EV: figures in R, using the same calculation results
  -> EI: findings
  -> ER: independent review
  -> existing human checkpoint
  -> host: scoped handoff
```

These are five workflow responsibilities. The normal pass has three model operations: `EP-plan`, `EI-findings`, `ER-review`. No default call per dataset or figure, and no additional handoff model call. The independent reviewer receives bound evidence and outputs in a fresh context. Targeted correction may revisit the affected component; it must not create an indefinite review loop.

## Source of truth and files

- [Component and rule registry](../../rules/eda/eda_rules.json): names, order, execution type, input/output contracts, EDA001-EDA009, runtime status and reference hash. This is the single configuration source.
- [Scientific reference](../../rules/eda/eda_scientific_reference.txt): unchanged snapshot of the reviewed English text, including all 15 data categories, 16 drawing specifications, MP background/locators and WEB sources. Original path and SHA-256 are in the registry. Its text-review status describes the reference's authoring scope.
- [Model prompts](../../prompts/stage_contracts/v1/eda.txt): selected operation blocks for EP, EI and ER only.
- [Python scaffold checker](../research_pipeline/eda_framework.py): reads contracts, checks their consistency and optionally loads the R scaffold. It does not ingest project data, call a model or run EDA.
- [EC interface](../../../pkpd_r/eda/calculate.R): reserved `eda_calculate(plan, data_bundle, output_dir)`.
- [EV interface](../../../pkpd_r/eda/visualize.R): reserved `eda_visualize(plan, calculation_bundle, output_dir)`.
- [R worker](../../../pkpd_r/eda/worker.R): standalone `--check` entry; resolves `PKPD_R_LIB` using the existing project convention. It does not source the downstream fitting/integration loader.

## Shared contracts

The registry's `artifact_contracts` lists required fields and relationships. These are authoring contracts; executable response-schema enforcement is pending.

Every future artifact must bind its input, plan, rules, prompts and reference version. Preserve raw values/source IDs, formulas and their definitions, operands, units, time origins/windows, grouping, experimental units, transformation/aggregation order and missing/censored handling. Changed bytes invalidate dependent results/reviews and human confirmation.

EC will retain an R results object plus reviewable tables. EV will consume that same object; it will not recompute a separate statistic for display. Figures will expose their exact plotted rows, captions, omissions and source links. PNG previews and SVG/PDF exports are planned. None of these analysis outputs are generated by the scaffold.

Data already owns cleaning, Coverage and Necessity. EDA reuses those decisions and routes newly discovered input defects back to Data. Validity of the whole input package and calculability of an individual formula are distinct. Missing local inputs or unresolved source conflicts restrict dependent work while unaffected descriptions may continue.

## Scientific scope

Allowed: established, assumption-free descriptive formulas with complete supported inputs. Examples include documented unit conversion/time alignment, nonzero-dose normalization, defined response transformations, matched ratios from existing quantities, complete measured collection totals, explicitly maximum observed concentrations, and statistics at verified unit/group levels. Supported bounds remain bounds.

Deferred: new AUC/AUMC or response-time integration, exposure reconstruction, terminal-slope selection, PK parameter estimation beyond explicitly permitted descriptive quantities, PD-target fitting, inferential uncertainty, human simulation and PTA. Existing analytical outputs may be displayed with their definitions and provenance. Combination therapy is excluded; covariate analysis and allometric/parameter-weight plots are deferred.

Figure families are selected from the shared reference rather than implemented as separate agents: animal PK, PD effect range, and compatible exposure/index-response, with conditional binding/stability/urine/MIC displays. Tables, annotations or shared panels often suffice. MP background remains available without creating mandatory plots or new task requirements.

## Current implementation boundary

Implemented: five named component contracts, shared reference binding, three operation prompts, static Python checker and loadable R interfaces.

Pending: Data-to-EDA adapter, executable response schemas, descriptive R handlers, figure templates, artifact version enforcement, model request builders, repair/handoff logic and workflow/UI wiring. ## Offline framework check

From the repository root in PowerShell:

```powershell
& '.venv-context/Scripts/python.exe' -m research_pipeline.eda_framework --check-r
```

The existing Rscript resolver uses `PKPD_RSCRIPT`, the project's ScienceEnv default, then PATH. `PKPD_R_LIB` controls the R library location. The check reports package availability and actual R version. It checks scaffold consistency/loading only; it does not validate any formula, figure, dataset or scientific conclusion.
