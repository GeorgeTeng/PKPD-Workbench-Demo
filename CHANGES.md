# Connected demo integration

This distribution wraps the existing local scientific source snapshot. The original source checkout is not modified. The imported file hashes and distribution differences are recorded in `validation/source-provenance.json`; they do not imply that the original checkout had a clean Git history.

## Application changes

- Added an explicit lightweight Data profile: source-preserving preparation and host QC, with scientific coverage left unassessed and all findings/gates retained.
- Added read-only agent-to-agent request, model-input, response and receipt inspection within Research stages.
- Exposed provider/model/API-base launch options; new calls default to `gpt-6.1-sol` / `high`. Historical identities remain unchanged.
- Added resumable sequential acceptance of PMB, Meropenem and Voriconazole, with independent artifact and Human-gate checks.
- Reused the approved green and white research interface with a separate knowledge workspace.
- Connected file imports, native workflow execution and signature-bound checkpoint controls through Data.
- RAG and ContextBuilder pages explain their functions and relationship. Removed manual retrieval/assembly controls and result panels; the knowledge library remains browsable.
- Added persistent, report-bound review notes without changing scientific permissions.
- Added the three actual example input ZIPs and per-file checksums.
- Replaced unsupported stage actions with explicit planned or recorded views, including the EDA and PK figure galleries.
- Removed the superseded dashboard and duplicate copies of native frontend assets.
- Added a self-contained Windows Python runtime, launcher, stop script and English documentation.

## Backend compatibility fixes

- Added an explicit demo-only deferral for a sole Context canonical-placement issue after all scientific preservation checks pass. The original independent REVISE, unchanged candidate, bound receipt and open findings remain visible through the Data Human gate. Full mode and scientific preservation failures still block.
- A complete retained Context is verified before attempting another model dispatch. Explicit technical continuation preserves earlier failed dispatch ledgers and records reuse without rerunning compression or review.

- File intake executes its deterministic contract directly and leaves the original receipt for Context. Fresh Context revisions also complete intake before launching their Context worker.
- Connected canvas runs complete Rules after compression before collecting Context outputs. The explicitly configured demo performs one source-bound key-Rules extraction and records provisional automatic acceptance; normal source workflows retain independent Rules review. A verified-output recovery endpoint can retain an already passed Context after missing Rules are supplied.
- Context import verifies both file references, then compares complete JSON content so serialization whitespace does not invalidate an unchanged handoff.
- The demo always exposes a final Data Human gate, including technically clean results.
- Retained Data labels rebind unchanged Context content and inventory references into the new attempt while preserving the original model identity. Preparation keeps the exact approved demo scope, and handoff cleanup targets only publication outputs rather than archiving its own source inputs.
- Scheduler completion and graph diagnosis now recognize source-verified provisional demo Rules only when that profile was explicitly selected. The publication status and deferred scientific review remain unchanged; successful model outputs can be recovered without repeating compression or Rules extraction.
- Context, Data scope and completed-Data checkpoints are visible in the main interface, including locked states and automatic acceptance records. Their forms call the original signature-bound review endpoint.
- Removed the generic ContextBuilder link repeated on every research substep; the dedicated Knowledge & context workspace remains available.
- The Codex adapter passes the configured model and `high` explicitly and binds reasoning effort to invocation/cache identity.
- Removed the default Data model timeout and the wall-clock budget for newly created Context runs. Key-Rules already waits without a timeout. The acceptance runner no longer imposes a stage deadline; manual Pause remains available.
- Data dispatch receipts are scoped to the live run and exact request. An explicit retry creates a new run; it no longer collides with a prior failed run's global request record. Duplicate calls within the same run remain blocked.
- Requirements generation selects source IDs and literal quotation spans from the supplied context, Rules and method sources. Shared schema definitions avoid duplicating the source catalog. Original source text, stored model responses and strict host evidence validation remain unchanged.
- Method-derived requirements cannot be generated as source permissions. Project-evidence requirements retain that category; draft methods may identify a prerequisite but cannot authorize data access.
- Data access accepts both a verified `main:/...` source ID and its `/...` JSON pointer. Explicit response reuse can retain a completed model response only when its full request and executor match; source hashes and current stage checks still apply, and reuse receipts distinguish it from a new model call.
- Data access also resolves an existing Context object or array pointer into its exact source-map descendants. Unknown paths still fail, and path boundaries prevent one item from selecting similarly numbered neighbors.
- Stated-value fields that the model did not copy literally are retained as unresolved metadata, with a Human-review finding before EDA. Source evidence and the original model response remain intact; unsupported annotations are never adopted as copied measurements. Literal numerical values and units remain unchanged.
- Footnote measurements may retain table-row citations that establish their applicability. The measurement and its qualifiers must still be supported outside the table body; a body-only number cannot become a separate text measurement.
- Column positioning separates the exact copied header from supplemental unit citations. A unique literal match identifies the column; ambiguous repeated headers still fail rather than selecting a position heuristically.
- In the explicit lightweight profile, unsupported column unit/qualifier annotations become unresolved metadata with a Human-review finding. Mixed-unit rows remain intact and no common unit or conversion is inferred. Original responses and citations remain available; the full route retains its strict literal-unit validator.
- The lightweight profile keeps annotations from linked notes, nested headers or ambiguous positions as explicit unmapped-column review findings. They are never assigned to an unrelated table column. Source rows remain intact; formal column binding still rejects these cases outside the demo profile.
- `compression.extract` accepts the original revision adapter's two explicit metadata fields, `revision_feedback` and `revision_policy`. Unknown fields remain rejected and revision feedback remains outside the scientific evidence sections.
- Source-preserving extraction revisions carry the exact reviewed candidate as a non-authoritative editable draft. Its digest is checked against the review. Replacement-proposal requests do not inherit this draft, and independent review still receives only current sources and the new candidate.
- Linear execution errors now carry a timestamp so the workbench can classify current failures. The compatibility reader recovers older missing timestamps only when the two retained error copies agree and both belong to the current attempt.

## Execution boundaries

The current native Data route defines requirements alongside the source inventory, then performs source access, labeling and adequacy. The earlier label-first design is labelled as a target workflow in the interface. No alternative ordering is silently claimed as already connected.

Model-backed acceptance stops at Data. Automatic checkpoint decisions require the acceptance script's explicit authorization flag and retain their test-only scope. EDA, PK fitting and scientific release are not part of this acceptance.

The release packager requires all three independently verified example acceptances through Data, matching driver artifacts and current SHA-256 bytes. Failed attempts and their raw diagnostics remain local in `state/`; a passing release includes separate read-only snapshots for all three examples and their acceptance history.
# Additional Data annotation handling

The technical demo leaves fields supported only by table-body evidence unresolved in note annotations, while preserving original source rows, citations and raw model responses. `STATED_LOCATION_UNRESOLVED` findings carry the proposed metadata into Human review before EDA. Full-route validation and literal citation checks remain strict.
